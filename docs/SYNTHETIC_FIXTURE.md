# Synthetic integration fixture

## Purpose

The fixture tests whether the public R implementation can execute from raw,
OptionMetrics-shaped CSV files through portfolio optimization without access to
licensed observations. It is deterministic and entirely generated by
`src/synthetic/generate_synthetic_inputs.R`.

It is not a simulated version of the research sample, an anonymized vendor
extract, or evidence about the paper's empirical findings. Reproducing the paper
still requires the documented OptionMetrics exports.

## Construction

The generator creates 13 monthly expiration blocks from December 2019 through
December 2020, which yield 12 usable decision-to-expiration periods under the
paper's lag convention. The raw option file has the exact 23-column contract in
`expected/raw_input_contract.csv` and contains:

- the four paper SecurityIDs for SPX, NDX, DJX, and RUT;
- calls and puts at five deterministic moneyness levels;
- a high-volume monthly contract and a lower-volume competing expiration;
- high-volume SPXW observations that must be excluded before contract selection;
- Saturday expiration dates that must become the preceding Friday; and
- positive bid and ask prices centered on deterministic Black--Scholes values.

Matching security-price rows provide decision and expiration closes. Each
decision date has three zero-curve maturities, including the exact option
maturity. Synthetic Yahoo-shaped index and ETF series have matched returns so
the known dividend adjustment is zero. Deterministic forecast and index-return
histories supply the remaining optimizer inputs.

## Execution and isolation

Run from the repository root:

```text
Rscript reproduce.R --synthetic --cores 2
```

Each run replaces only `work/synthetic/`. Generated raw files, configuration,
caches, and results all remain there and are ignored by Git, so the test cannot
overwrite licensed inputs or paper-vintage outputs.

## Validation

`src/synthetic/validate_synthetic.R` checks input hashes and row counts within
the run, exact schemas and filenames, every deliberately exercised selection
branch, Step 1 and Step 3 dimensions and completeness, every covered optimizer
mode, solvency and SPX margin diagnostics, and nine numerical regression
checkpoints in `expected/synthetic_checkpoints.csv`.

The checkpoint tolerances allow insignificant cross-platform floating-point
variation. They are deliberately not regenerated by the test itself: any change
requires a reviewed edit to the tracked expectation file.
